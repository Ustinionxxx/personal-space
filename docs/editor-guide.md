# 写字与发布

内容仓库必须保持 **Private**。第一次接入时，在 [Pages CMS](https://app.pagescms.org/) 用自己的 GitHub 登录，安装时只选择 `personal-space-content`。暂不邀请其他编辑者。

## 留下两句话或几张照片

1. 打开「生活记录」→ 新建。ID 自动生成，日期默认为今天，可以修改。
2. 标题可以空着。写几句话，或在「照片」中上传 JPEG、PNG、WebP，按需写图片说明。至少留下一种内容。
3. 保持「私密草稿」并保存。保存只把内容写进私有仓库，不会生成公开页面。
4. 想公开时，把状态选成「已发布」再保存。
5. 打开这个仓库的 **Actions → 发布个人网站**。等待本次运行变绿，在运行摘要点击「打开网站」。后台显示保存成功，只表示 GitHub 已保存；网站部署成功看 Actions 结果。

后台「重新发布 / 查看运行结果」也可以手动重试构建，并查看该次运行状态。所有自动保存触发的记录都在 GitHub Actions 中。

## 照片与文字

图片库中的文件、尚未发布的记录都不会直接暴露到网站。只有已发布内容引用的图片会生成网页版本。横竖照片都保留完整比例，发布时去掉 EXIF；原图还在私有仓库。

正文支持常用 Markdown 排版，也可以切换源码。正文里的图片请从后台图片库选择。原始 HTML 不渲染，外部图片地址不接受；需要展示外部项目时用普通链接。

标题随时改，记录地址不会随之变化。不要手动改 ID。旧站记录保留了原有的链接标识。

## 关于、首页与项目

- 「个人介绍」是 About 的唯一内容源。修改正文，选为已发布并保存即可。
- 「首页设置」可改短介绍、「最近在……」、联系入口、首页项目。空白的近况与邮箱不会显示；只有已发布的项目可以展示。
- 「项目」可以进行中、已完成或暂时搁置。自由写，但请交代项目是什么、你实际参与了什么。源码、演示、过程链接均可不填。
- 旧站示例与 BiliNote 已保留为待整理草稿，日期留空，不能直接误发布。删掉整理提示，补充真实内容和日期后再发布。

## 撤回与失败

改回草稿并保存，等下一次部署成功后，记录会从当前网站撤下。已经公开过的内容可能还存在于缓存、旧部署或别人的副本中，不能重新视作保密内容。

构建失败时，Actions 会显示失败步骤，例如字段不完整或图片找不到。改好后重新保存或用后台重新发布。构建失败不会上传任何产物，之前成功的网站继续可用。

没有公开草稿预览。编辑器里可以看图文内容，实际网站只显示已发布记录。
